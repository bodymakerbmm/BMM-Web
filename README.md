# BMM Web v0.3

第一段階・第二段階の土台です。GitHub Pages上で動くHTML/CSS/JavaScriptのみで構成しています。

## 現在動く機能
- 複数店舗のGoogleスプレッドシート読込
- 店舗・期間フィルター
- 売上、売れ数、商品種類、平均単価
- 商品検索
- 売上／売れ数ランキング
- 店舗比較
- 棚別分析（棚番号列がある場合）
- ABC分析
- 期間比較
- 在庫表示（在庫列がある場合）
- PC・スマホ対応
- 読込データと設定をブラウザ内にキャッシュ
- デモデータ表示

## データの場所
GitHubへ置くのは index.html / CSS / JavaScript だけです。
読み込んだ売上データはGitHubへ書き込まず、利用中のブラウザの localStorage に保存します。

Googleスプレッドシートの共有設定は「リンクを知っている全員・閲覧者」を前提にしています。
その設定では、URLを知る人がシートを閲覧できる点を理解した上で運用してください。

## 現在の列設定
画像から次の列として設定しています。
- A: JAN
- B: 品番
- C: 売れ数
- D: 売上金額
- E: 店舗名
- F: 日付
- H: 商品名

棚番号と在庫の列は、実データを確認後に設定画面で指定できます。

## ローカル確認
ZIPを展開し、index.htmlを直接開いてデモ表示できます。
Googleスプレッドシート連携はブラウザの制約により、GitHub PagesまたはローカルHTTPサーバー上で確認してください。

Windowsで簡易確認:
1. このフォルダーでコマンドプロンプトを開く
2. `python -m http.server 8000`
3. `http://127.0.0.1:8000` を開く

## GitHub Pages公開
1. GitHubで新しい公開用リポジトリを作成
2. このフォルダーのファイルをアップロード
3. Settings → Pages
4. Deploy from a branch
5. main / root を指定して保存

## 実データ接続前に必要なもの
各店舗について次の2点だけです。
- 店舗名
- GoogleスプレッドシートURL

シート名が複数ある場合だけ、対象シート名も入力します。


## v0.2：週次履歴の蓄積
- Googleスプレッドシートが翌週データへ上書きされても、取得済みの過去週はブラウザ内に残ります。
- 同じ週を再同期した場合、その週の日付分を新しい内容で置き換えるため二重計上しません。
- 「保存履歴」画面で保存期間・行数・同期履歴を確認できます。
- 履歴をJSONファイルへバックアップし、別PC・別ブラウザへ復元できます。

重要：
履歴は中央サーバーではなく、BMM Webを使ったPC・ブラウザごとに保存されます。
全社員が同じ履歴を自動共有する機能は、将来の会社サーバー版で実装します。


## v0.3：自動同期＋3年保存
- BMM Webを開くと、各端末が登録済みGoogleスプレッドシートを自動確認します。
- 本部や東大阪PCで代表者が更新する必要はありません。
- 東大阪、名古屋、江坂など、登録済み全店舗を各端末が直接取得します。
- 履歴はIndexedDBへ保存し、直近3年分を保持します。
- 3年より古い日付は同期時に自動整理します。
- 同じ店舗・同じ日付を再同期すると、その日の古い内容を置き換えるため二重計上しません。
- 手動の「今すぐ更新」ボタンも残しています。
- v0.1 / v0.2のブラウザ内データがあれば初回起動時に移行します。

### 第二段階での重要な制約
履歴は端末ごとのブラウザ内に保存されます。
各スマホ・PCは、BMMを開くたびに最新週を自動取得します。
過去3年分を新しい端末へ移す場合は「履歴をバックアップ」「バックアップを復元」を使用します。
