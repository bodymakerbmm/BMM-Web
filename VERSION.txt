BMM Web Version 3.2.0 在庫共通保存版
作成日: 2026-08-18

■今回の修正目的
週次在庫ExcelをどのPCから取り込んでも、Google Apps Script + 共通BMMスプレッドシートへ保存し、他PC/他ブラウザの「今すぐ更新」で同じ在庫を取得できるようにする。

■重要な修正
1. 在庫Excelの0在庫も保存対象に変更。
   0を「在庫データなし」と同一視しない。
2. 在庫共通保存先「在庫履歴」をGoogleスプレッドシートへ追加。
3. 1店舗×1基準日を複数チャンク(JSON)に分割保存。
   1セルの容量制限を避けるため、1チャンク700件。
4. 同じ店舗・同じ基準日の再取込は、そのスナップショットだけを置換。
5. 最大3年前までの在庫履歴を保持。
6. 「今すぐ更新」時に共有在庫を取得し、ローカルIndexedDBへ反映。
7. 在庫Excel取込時に共有APIへ即時保存。
8. 店舗列名が「東大阪」/「東大阪店」のように末尾の「店」が違っても登録店舗へ正規化。
9. 売上3年共有履歴、商品マスタ、棚データ、ABC、ランキング、期間比較等の既存機能を維持。

■週次在庫形式の確認
既存監査記録に基づき、JAN/品番/品名/オンライン価格/F列以降の店舗列という形式を維持。
店舗列は固定列番号ではなく、ヘッダーから自動判定。

- app.js JavaScript構文: OK
- core.js JavaScript構文: OK
- db.js JavaScript構文: OK
- GoogleAppsScript_Code.gs JavaScript構文: OK（Apps Script構文として静的確認）
- app.js → index.html DOM参照: 欠落0
- 実データ構造サンプル（親コード/JAN/品番/品名/オンライン価格/ららぽーと堺店/江坂店/東大阪店/名古屋店）: OK
- 4店舗×3商品=12在庫レコード生成: OK
- 0在庫9件を含む全12件保持: OK
- 0在庫を除外しないこと: OK
- 店舗列自動判定: OK
- 店舗名「東大阪」/「東大阪店」の正規化: OK
- 共有在庫POST処理の存在確認: OK
- 共有在庫GET処理の存在確認: OK
- 在庫履歴チャンク保存処理の存在確認: OK
- 売上共有履歴処理を維持: OK

■実環境で必要な最終確認
この実行環境からGoogle Apps Scriptの実Webアプリを操作することはできないため、以下はユーザー環境で一度だけ確認する。
1. Apps Scriptコードを3.2.0へ更新。
2. setupBMMHistoryを実行して「在庫履歴」シートを作成。
3. Webアプリを「新バージョン」で再デプロイ。
4. BMM 3.2.0をGitHub Pagesへ反映。
5. 任意のPCで週次在庫Excelを取り込み、「今すぐ更新」。
6. 別PCでCtrl+F5→「今すぐ更新」し、同じ現在庫が表示されることを確認。
7. 0在庫商品が0として表示され、売上がある場合のみ「欠品」判定になることを確認。

※上記7項目の実Web/E2Eだけは、Googleアカウント・GitHub Pages・実Excelを使用するため、この環境では実行できない。ここを「完全に実機検証済み」とは表記しない。


3.2.0仕様修正: 在庫は3年履歴ではなく、最新の週次在庫スナップショット1件のみGoogle側で共有保存します。新しい基準日の取込時に旧共有在庫を置換し、同一基準日は上書きします。古い基準日の取込は既存の最新データを保護するため保存しません。0在庫は保存対象です。
